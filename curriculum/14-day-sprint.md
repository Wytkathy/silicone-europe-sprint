# 14-Day Coached Sprint

Use the same loop every day: **learn → attempt → ask Codex to review → correct
your work → explain it back → record evidence**. Do not accept code you cannot
explain.

## Daily Rhythm

| Block | Time | Output |
|---|---:|---|
| Market development | 3h | Research or outreach artifact |
| Figma/design | 2h | Frame, component, or critique |
| Web development | 5h | Working page increment |
| Codex review | 1h | Findings and corrections |
| Reflection | 1h | Learning log and next action |

## Day 1 — Direction and HTML

- Read `research/market-analysis.md`; challenge the selected market.
- Learn semantic HTML and inspect `site/index.html`.
- Replace one paragraph in the hero without breaking its meaning.
- **Explain back:** Why Germany, why kitchenware, and what `<main>` does.

## Day 2 — ICP and CSS

- Read the ICP and scoring model; score three new candidates.
- Learn box model, Flexbox, typography, and tokens in `styles.css`.
- Change one spacing token and observe all affected sections.
- **Challenge:** Rebuild one card without copying its CSS.

## Day 3 — Sources and Figma Foundations

- Validate the first ten account URLs and separate facts from hypotheses.
- In Figma, inspect frames, Auto Layout, components, and shared styles.
- Recreate the homepage hero at desktop and mobile sizes.
- **Explain back:** Difference between a fact, signal, and opportunity hypothesis.

## Day 4 — Value Proposition and Wireframes

- Write one value proposition for a buyer, product lead, and brand lead.
- Map each homepage section to a buyer question.
- Produce a low-fidelity mobile homepage wireframe.
- **Challenge:** Remove one section and defend the decision.

## Day 5 — Visual System

- Extend the target list review to 20 accounts.
- Inspect typography, colors, spacing, buttons, and cards in Figma.
- Create one alternative card and button state.
- **Explain back:** Why consistency builds B2B trust.

## Days 6–7 — Homepage Development

- Read and annotate the homepage HTML and CSS.
- Rebuild one section from scratch in a new scratch file.
- Test navigation and mobile layout.
- Ask Codex for a review, fix findings, then explain each fix.

## Day 8 — Optimization

- Review all 30 accounts and adjust scores using evidence.
- Improve one CTA and one section heading.
- Run typecheck, tests, and build.
- Audit page hierarchy, keyboard use, metadata, and responsive behavior.

## Day 9 — Deep Profiles and Landing-Page Strategy

- Review `deep-profiles.md`; validate two profiles independently.
- Map product-page sections to likely objections.
- Draft a different product angle for a retailer and a DTC brand.

## Day 10 — Landing-Page Design

- Recreate the product page in Figma.
- Produce a premium consumer-brand hero variant.
- Produce a minimal technical-manufacturing hero variant.
- Select a winner based on the ICP, not personal taste.

## Days 11–12 — Landing Page and Outreach

- Read and annotate `product.html`.
- Add one FAQ item with accessible interaction.
- Draft personalized emails for two accounts using only sourced facts.
- Run a Codex fact-risk review before considering either email usable.

## Day 13 — Simulation and Publishing Readiness

- Role-play no reply, incumbent supplier, MOQ mismatch, and sample request.
- Test links, controls, mobile layouts, accessibility, and build output.
- Replace placeholder claims before any real publication.

## Day 14 — Independent Assessment

- Research one new account and create a sourced profile.
- Design and build a simplified hero within three hours.
- Write one personalized email and label every factual basis.
- Complete the checklists and write a one-page retrospective.

## Daily Codex Prompt

```text
Goal:
Context:
My current understanding:
Constraints:
Done when:

Act as my coach. Ask me to attempt the next small step first. Review my work,
explain errors, and do not replace the entire solution unless I am blocked.
```
